Why Galley exists

See the edits.
Follow the idea.

A useful review starts with understanding the change.

A pull request can span a proposal, a README and several source files. To review it well, your team needs to follow the explanation, inspect the edits and connect the discussion to the right text.

Galley brings those parts into one readable view. Documents keep their headings and tables. Code keeps its line numbers. Changes stay beside the context that helps you understand them.

More context for every reviewer. Ask a question beside the change, reply in the same thread, and keep the discussion on GitHub or GitLab.

  1. 01 · Open the review

    Press Read on your GitHub pull request or GitLab merge request.

  2. 02 · Read with context

    Follow the document as an article. Turn on Code files to include source changes.

  3. 03 · Inspect the edits

    See changed words in their sentences and changed code with line numbers. Expand unchanged sections when you need more context.

  4. 04 · Discuss the change

    Add comments and replies beside the relevant text. Your team sees them in the original review.

  5. 05 · Keep your place

    Mark files as viewed as you go, then return to GitHub or GitLab to submit your review.

How Galley helps

Context for the change.
Space for the discussion.

Read the proposal, inspect the code and discuss the details in one view. These features help your team understand what changed before deciding what to do next.

  1. 01

    Make the content readable.

    Read documents with headings, tables, task lists and diagrams. Include code files with syntax colours, line numbers and long lines that wrap to fit the screen.

    Follow the explanation and the implementation.

  2. 02

    See edits in context.

    Added words are highlighted and removed words struck through inside their sentences. Table edits appear in their cells, and changed link destinations are called out.

    Understand the detail and the surrounding idea.

  3. 03

    Focus on what changed.

    Re-wrapping a paragraph doesn’t mark it as a text change. Unchanged sections fold away; open them whenever you need the context.

    Your scrollbar gets a breather.

  4. 04

    Discuss it beside the text.

    Read threads beside the paragraph or code line they discuss. Select text to add a comment, reply in the thread, and keep your draft while you read on.

    Teammates can reply on GitHub or GitLab.

  5. 05

    Find your reading comfort.

    Choose from nineteen palettes, six typefaces, five text sizes and six layouts. Use light or dark mode, compact spacing and keyboard shortcuts.

    Adjust the view to suit your screen and your eyes.

  6. 06

    Keep your work on your code host.

    Files render in your browser and comments go to the original review. Galley has no server, account or analytics. External images load only when you choose.

    Works with your team’s existing review process.

Available in the Chrome Web Store

Start with three steps.

  1. 01

    Open Galley in the Chrome Web Store.

  2. 02

    Choose Add to Chrome, then confirm Add extension.

  3. 03

    Open a GitHub pull request or GitLab merge request and press Read.

No Galley account needed. Private GitHub repositories need a token; see the setup details below.

Do my teammates need Galley?

No. Comments and replies appear in the original GitHub or GitLab review. Teammates can read and respond there, whether or not they use Galley.

Can I review code as well as documents?

Yes. Markdown documents open as readable articles. Turn on Code files in Reading settings → Review to include supported source and configuration files, with syntax colours, wrapped lines and comments beside the code.

Does it work with private repositories?

Yes. GitLab uses your signed-in session. Private GitHub repositories need a fine-grained token, saved in the extension: read-only Contents and Pull requests to read, plus Pull requests write access to comment.

Self-hosted GitLab and GitHub Enterprise Server are enabled one domain at a time from the extension popup. Read the setup guide ↗

Where do my files and comments go?

Galley loads files from your GitHub or GitLab site and renders them in your browser. Comments go back to that review when you post. There is no Galley server or analytics. The demo keeps comments in your browser session and doesn’t post to either platform.

Read the full privacy policy →

Which browsers does it support?

Chrome, and Chromium browsers such as Edge, Brave and Arc, from the Chrome Web Store. A Firefox build comes with every GitHub release; the Firefox Add-ons listing isn’t published yet. Safari isn’t packaged.

How does it help my team review changes?

Galley puts readable content, edits and discussion in one view. Reviewers can follow the proposal, inspect a change in context and ask a question beside it. We haven’t measured review speed; the focus is helping people understand the work.

Can I approve a request from Galley?

You can read, comment, reply and mark files as viewed in Galley. Return to GitHub or GitLab to approve the request, request changes or resolve a thread.
